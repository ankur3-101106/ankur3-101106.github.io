String Matching & NP-Completeness​

1. Introduction to String Matching​

1.1 Problem Definition and Formal Model​

The string-matching problem formalizes the task of locating all valid occurrences of a given pattern string within a larger body of text.

  • Text: Modeled as an array T[1…n]T[1 \dots n]T[1…n] of length nnn.
  • Pattern: Modeled as an array P[1…m]P[1 \dots m]P[1…m] of length mmm, where m≤nm \le nm≤n.
  • Both TTT and PPP are composed of character elements chosen from a finite alphabet Σ\SigmaΣ.
  • Valid Shift: We say that pattern PPP occurs with shift sss in text TTT if: 0≤s≤n−mandT[s+1…s+m]=P[1…m]0 \le s \le n - m \quad \text{and} \quad T[s + 1 \dots s + m] = P[1 \dots m]0≤s≤n−mandT[s+1…s+m]=P[1…m] If PPP occurs with shift sss in TTT, then sss is called a valid shift; otherwise, it is an invalid shift.

1.2 Applications in Modern Computing​

  • Text Editing & Word Processors: Find and replace tools, syntax highlighting, spelling correctors.
  • Search Engines & Information Retrieval: Indexing and fast retrieval of queries across internet documents.
  • Bioinformatics & Computational Genomics: Locating specific nucleotide (DNA/RNA: {A,C,G,T}\{A, C, G, T\}{A,C,G,T}) or amino acid sequence motifs.
  • Cybersecurity & Network Intrusion Detection: Inspecting packet payloads against known malicious signatures (e.g., Snort rules).

2. Naive String Matching Algorithm​

2.1 Working Principle and Shift Exploration​

The Naive String Matching algorithm finds all valid shifts by systematically testing every possible shift s∈{0,1,…,n−m}s \in \{0, 1, \dots, n - m\}s∈{0,1,…,n−m}:

  • For each shift sss, it performs a character-by-character comparison between P[1…m]P[1 \dots m]P[1…m] and the text window T[s+1…s+m]T[s + 1 \dots s + m]T[s+1…s+m].
  • As soon as a mismatch is detected, it shifts the pattern forward by exactly 1 position (s←s+1s \leftarrow s + 1s←s+1) and restarts comparison from the first character of PPP.

2.2 Algorithm Pseudocode​

NAIVE-STRING-MATCHER(T, P)
n = T.length
m = P.length
for s = 0 to n - m do
    if P[1..m] == T[s + 1 .. s + m] then
        print "Pattern occurs with shift " s

3. Rabin-Karp Algorithm​

3.1 Hash-Based String Matching Concept​

The Rabin-Karp algorithm speeds up string matching by comparing numerical hash values of the pattern and text windows before performing character-by-character verification:

  1. Treat characters as digits in a radix-ddd positional notation (where d=∣Σ∣d = |\Sigma|d=∣Σ∣).
  2. Compute the hash value ppp for the pattern P[1…m]P[1 \dots m]P[1…m].
  3. Compute the hash value tst_sts​ for each sliding text window T[s+1…s+m]T[s + 1 \dots s + m]T[s+1…s+m].
  4. If p==tsp == t_sp==ts​, perform a character verification to guard against spurious hits (hash collisions).

3.2 Radix Notation and Rolling Hash Formula​

To prevent large integers from causing arithmetic overflow, calculations are performed modulo a large prime qqq:

  • Pattern hash: p=(P[1]⋅dm−1+P[2]⋅dm−2+⋯+P[m]) mod qp = (P[1] \cdot d^{m-1} + P[2] \cdot d^{m-2} + \dots + P[m]) \bmod qp=(P[1]⋅dm−1+P[2]⋅dm−2+⋯+P[m])modq
  • Initial text window (s=0s = 0s=0): t0=(T[1]⋅dm−1+T[2]⋅dm−2+⋯+T[m]) mod qt_0 = (T[1] \cdot d^{m-1} + T[2] \cdot d^{m-2} + \dots + T[m]) \bmod qt0​=(T[1]⋅dm−1+T[2]⋅dm−2+⋯+T[m])modq
  • Precomputed constant: h=dm−1 mod qh = d^{m-1} \bmod qh=dm−1modq
  • Rolling Hash Formula (compute ts+1t_{s+1}ts+1​ from tst_sts​ in O(1)O(1)O(1) time): ts+1=(d⋅(ts−T[s+1]⋅h)+T[s+m+1]) mod qt_{s+1} = \left( d \cdot (t_s - T[s + 1] \cdot h) + T[s + m + 1] \right) \bmod qts+1​=(d⋅(ts​−T[s+1]⋅h)+T[s+m+1])modq

3.3 Spurious Hits vs. Valid Matches​

  • Valid Match: When ts≡p(modq)t_s \equiv p \pmod qts​≡p(modq) AND T[s+1…s+m]==P[1…m]T[s + 1 \dots s + m] == P[1 \dots m]T[s+1…s+m]==P[1…m].
  • Spurious Hit: When ts≡p(modq)t_s \equiv p \pmod qts​≡p(modq), but T[s+1…s+m]≠P[1…m]T[s + 1 \dots s + m] \ne P[1 \dots m]T[s+1…s+m]=P[1…m] (a hash collision due to the modulo operation).

3.4 Algorithm Pseudocode​

RABIN-KARP-MATCHER(T, P, d, q)

m = P.length

p = 0
t0 = 0

// Preprocessing

    p = (d * p + P[i]) mod q

        ts+1 = (d * (ts - T[s + 1] * h) + T[s + m + 1]) mod q

4. String Matching with Finite Automata (FA)​

4.1 5-Tuple Automaton Model​

A string-matching automaton is a deterministic finite state machine defined by the 5-tuple:

M=(Q,q0,A,Σ,δ)M = (Q, q_0, A, \Sigma, \delta)M=(Q,q0​,A,Σ,δ)
  • Q={0,1,…,m}Q = \{0, 1, \dots, m\}Q={0,1,…,m}: Set of states, where state qqq denotes that a prefix of length qqq of PPP has been matched.
  • q0=0q_0 = 0q0​=0: Initial state (no characters matched yet).
  • A={m}A = \{m\}A={m}: Accepting state (indicating a complete match of P[1…m]P[1 \dots m]P[1…m]).
  • Σ\SigmaΣ: Finite input alphabet.
  • δ:Q×Σ→Q\delta: Q \times \Sigma \to Qδ:Q×Σ→Q: State transition function.

4.2 Suffixes and Prefix-Suffix Matching Concept​

  • Suffix Notation: ω⊐x\omega \sqsupset xω⊐x indicates that string ω\omegaω is a suffix of string xxx.
  • Prefix Function σ(x)\sigma(x)σ(x): The length of the longest prefix of PPP that is also a suffix of xxx: σ(x)=max⁡{k:Pk⊐x}\sigma(x) = \max \{k : P_k \sqsupset x\}σ(x)=max{k:Pk​⊐x}
  • The state transition function is defined as: δ(q,a)=σ(Pqa)\delta(q, a) = \sigma(P_q a)δ(q,a)=σ(Pq​a)

4.3 Transition Function Computation (δ\deltaδ)​

COMPUTE-TRANSITION-FUNCTION(P, Sigma)
m = P.length
for q = 0 to m do
    for each character a in Sigma do
        k = min(m + 1, q + 2)
        repeat
            k = k - 1
        until P_k is a suffix of P_q a
        delta(q, a) = k
return delta

5. Knuth-Morris-Pratt (KMP) Algorithm​

5.1 Motivation: Eliminating Text Backtracking​

The Knuth-Morris-Pratt (KMP) algorithm eliminates the need to backtrack the text pointer iii:

  • When a mismatch occurs after matching qqq characters, the pattern itself contains information about where the next possible match could begin.
  • It precomputes a Prefix Function π\piπ (or LPS Array - Longest Proper Prefix which is also a Suffix).

5.2 Proper Prefixes, Proper Suffixes, and the π\piπ Function​

  • Proper Prefix: A prefix of string SSS that is strictly shorter than SSS (Pk⊏SP_k \sqsubset SPk​⊏S).
    • For "Snape": {"S", "Sn", "Sna", "Snap"}.
  • Proper Suffix: A suffix of string SSS that is strictly shorter than SSS (Pk⊐SP_k \sqsupset SPk​⊐S).
    • For "Hagrid": {"agrid", "grid", "rid", "id", "d"}.
  • Prefix Function π[q]\pi[q]π[q]: π[q]=max⁡{k:k<q and Pk⊐Pq}\pi[q] = \max \{k : k < q \text{ and } P_k \sqsupset P_q\}π[q]=max{k:k<q and Pk​⊐Pq​} π[q]\pi[q]π[q] stores the length of the longest proper prefix of PPP that is also a proper suffix of P[1…q]P[1 \dots q]P[1…q].

5.3 Prefix Function Computation Algorithm​

COMPUTE-PREFIX-FUNCTION(P)
m = P.length
pi[1] = 0
k = 0
for q = 2 to m do
    while k > 0 and P[k + 1] != P[q] do
        k = pi[k]
    if P[k + 1] == P[q] then
        k = k + 1
    pi[q] = k
return pi

6. String Matching Algorithms (Formal Procedures)​

6.1 Naive String Matching Algorithm​

Algorithm NaiveStringMatcher(T, P)
// Finds all occurrences of pattern P in text T by brute-force character checking
// Input: Text string T of length n, pattern string P of length m (m <= n)
// Output: Prints all valid shift positions s where P matches T[s+1 .. s+m]
{
    n <- length(T);
    m <- length(P);

    for s <- 0 to n - m do
    {
        j <- 1;
        while (j <= m and T[s + j] = P[j]) do
            j <- j + 1;

        if (j > m) then
            print "Pattern occurs with shift", s;
    }
}

6.2 Rabin-Karp Matching Algorithm​

Algorithm RabinKarpMatcher(T, P, d, q)
// Finds occurrences of pattern P in text T using rolling hash fingerprints
// Input: Text T of length n, pattern P of length m, radix d, prime modulus q
// Output: Prints all valid shift positions where P occurs in T
{
    n <- length(T);
    m <- length(P);
    h <- (d^(m - 1)) mod q;
    p <- 0;
    t <- 0;

    // Preprocessing: compute hash value of P and first window of T
    for i <- 1 to m do
    {
        p <- (d * p + P[i]) mod q;
        t <- (d * t + T[i]) mod q;
    }

    // Matching: slide pattern over text
    for s <- 0 to n - m do
    {
        if (p = t) then
        {
            // Verify character by character to eliminate spurious hits
            match <- true;
            for j <- 1 to m do
            {
                if (P[j] != T[s + j]) then
                {
                    match <- false;
                    break;
                }
            }
            if match then
                print "Pattern occurs with shift", s;
        }

        // Compute rolling hash for next window T[s+1 .. s+m]
        if (s < n - m) then
        {
            t <- (d * (t - T[s + 1] * h) + T[s + m + 1]) mod q;
            if (t < 0) then
                t <- t + q;
        }
    }
}

6.3 Knuth-Morris-Pratt (KMP) Matching Algorithm​

Algorithm KMPMatcher(T, P)
// Finds all occurrences of pattern P in text T in linear time without backtracking
// Input: Text string T of length n, pattern string P of length m
// Output: Prints all valid shift positions where P occurs in T
{
    n <- length(T);
    m <- length(P);
    pi <- ComputePrefixFunction(P);
    q <- 0; // Number of characters matched

    for i <- 1 to n do
    {
        while (q > 0 and P[q + 1] != T[i]) do
            q <- pi[q]; // Next character does not match, backtrack along pi

        if (P[q + 1] = T[i]) then
            q <- q + 1; // Next character matches

        if (q = m) then
        {
            print "Pattern occurs with shift", i - m;
            q <- pi[q]; // Look for next match
        }
    }
}

Algorithm ComputePrefixFunction(P)
// Computes auxiliary prefix function pi for pattern P
// Input: Pattern string P of length m
// Output: Array pi[1..m] storing length of longest proper prefix of P[1..q] that is also a suffix
{
    m <- length(P);
    pi[1] <- 0;
    k <- 0;

    for q <- 2 to m do
    {
        while (k > 0 and P[k + 1] != P[q]) do
            k <- pi[k];

        if (P[k + 1] = P[q]) then
            k <- k + 1;

        pi[q] <- k;
    }
    return pi;
}

7. Asymptotic Notation & Complexity Foundations​

7.1 Performance Analysis Definitions​

Asymptotic notations describe the behavior of algorithm running time as the input size nnn tends toward infinity.

7.3 Exponential Complexity and Infeasibility​

Algorithms running in O(2n)O(2^n)O(2n) or O(n!)O(n!)O(n!) time become computationally intractable even for moderate input sizes:

  • Example: Naive recursive calculation of Fibonacci numbers (T(n)=T(n−1)+T(n−2)≈O(1.618n)T(n) = T(n-1) + T(n-2) \approx O(1.618^n)T(n)=T(n−1)+T(n−2)≈O(1.618n)).
  • A computer computing fib(50) recursively would require over 101410^{14}1014 operations, stalling execution for days, whereas dynamic programming computes it in O(n)O(n)O(n) operations within microseconds.

8. Complexity Classes: P, NP, NP-Complete, and NP-Hard​

8.1 Class P (Deterministic Polynomial Time)​

  • Definition: The class of decision problems solvable in polynomial time by a deterministic Turing Machine (deterministic algorithm).
  • Running time is bounded by O(nk)O(n^k)O(nk) for some fixed constant kkk.
  • Examples:
    • Sorting algorithms (O(nlog⁡n)O(n \log n)O(nlogn))
    • Minimum Spanning Trees (O(Elog⁡V)O(E \log V)O(ElogV))
    • Shortest Path / Dijkstra (O(V2)O(V^2)O(V2) or O(E+Vlog⁡V)O(E + V \log V)O(E+VlogV))
    • Fractional Knapsack (O(nlog⁡n)O(n \log n)O(nlogn))

8.2 Class NP (Non-Deterministic Polynomial Time)​

  • Definition: The class of decision problems whose candidate solution (certificate/witness) can be verified in polynomial time by a deterministic algorithm.
  • Problems in NP are verifiable quickly, even if finding the solution requires exponential time via exhaustive search.
  • Key distinction: Finding a solution vs. verifying a proposed solution.

8.3 Class NP-Complete​

A decision problem XXX is NP-Complete if:

  1. X∈NPX \in NPX∈NP (solutions are verifiable in polynomial time).
  2. Every problem Y∈NPY \in NPY∈NP is polynomial-time reducible to XXX (Y≤PXY \le_P XY≤P​X).
  • Significance: NP-Complete problems are the hardest problems in NP. If any single NP-Complete problem is solved in polynomial time, then P=NPP = NPP=NP.
  • No polynomial-time algorithm is known for any NP-Complete problem.
  • Examples: Circuit-SAT, 3-SAT, Vertex Cover, Hamiltonian Cycle, 0/1 Knapsack (Decision).

8.4 Class NP-Hard​

A problem XXX is NP-Hard if every problem Y∈NPY \in NPY∈NP can be reduced to XXX in polynomial time (Y≤PXY \le_P XY≤P​X):

  • NP-Hard problems are at least as hard as NP-Complete problems.
  • Key distinction: NP-Hard problems do not need to be in NP (they do not need to be decision problems, nor verifiable in polynomial time).
  • Examples:
    • Traveling Salesperson Problem (Optimization)
    • Turing Halting Problem (Undecidable, hence not in NP, but NP-Hard)

8.5 P vs. NP Classification and Euler Diagram​

  • Fundamental Theorem: P⊆NPP \subseteq NPP⊆NP
  • If P≠NPP \ne NPP=NP: PPP and NP-CompleteNP\text{-Complete}NP-Complete are disjoint subsets of NPNPNP.

9. Polynomial-Time Reductions​

9.1 Concept of Problem Reduction (A≤PBA \le_P BA≤P​B)​

Let AAA and BBB be two decision problems. A polynomial-time reduction (A≤PBA \le_P BA≤P​B) is a deterministic algorithm that transforms any instance α\alphaα of problem AAA into an instance β\betaβ of problem BBB such that:

  1. The transformation executes in polynomial time (O(nk)O(n^k)O(nk)).
  2. The outputs are identical: α is a YES-instance of A  ⟺  β is a YES-instance of B\alpha \text{ is a YES-instance of } A \iff \beta \text{ is a YES-instance of } Bα is a YES-instance of A⟺β is a YES-instance of B.

9.2 Theoretical Implications​

  • Proving Tractability ("Easiness"): If B∈PB \in PB∈P and A≤PBA \le_P BA≤P​B, then A∈PA \in PA∈P. We use the efficiency of BBB to solve AAA.
  • Proving Intractability ("Hardness"): If AAA is known to be NP-Hard and A≤PBA \le_P BA≤P​B, then BBB is also NP-Hard.

10. Classic NP Problems & Hamiltonian Cycles​

10.1 Hamiltonian Cycle Problem​

  • Instance: A connected directed or undirected graph G=(V,E)G = (V, E)G=(V,E) with nnn vertices.
  • Hamiltonian Cycle: A round-trip closed loop along nnn edges that visits every vertex in VVV exactly once and returns to the initial vertex.
  • Decision Formulation: "Does graph GGG contain a Hamiltonian cycle?"

10.2 Polynomial Verification​

Given a proposed sequence of vertices C=⟨v1,v2,…,vn,vn+1⟩C = \langle v_1, v_2, \dots, v_n, v_{n+1} \rangleC=⟨v1​,v2​,…,vn​,vn+1​⟩:

  1. Verify v1==vn+1v_1 == v_{n+1}v1​==vn+1​.
  2. Verify all intermediate vertices v1,…,vnv_1, \dots, v_nv1​,…,vn​ are distinct.
  3. Verify that edge (vi,vi+1)∈E(v_i, v_{i+1}) \in E(vi​,vi+1​)∈E for all 1≤i≤n1 \le i \le n1≤i≤n.
  • Total verification time: O(V)O(V)O(V) operations   ⟹  \implies⟹ Hamiltonian Cycle ∈NP\in NP∈NP.

10.3 Backtracking Procedure for Finding Hamiltonian Cycles​

  1. Define a solution vector X=(X1,X2,…,Xn)X = (X_1, X_2, \dots, X_n)X=(X1​,X2​,…,Xn​) where XiX_iXi​ represents the iii-th visited vertex.
  2. Initialize X[1]=1X[1] = 1X[1]=1 (without loss of generality, start at vertex 1).
  3. For position kkk from 222 to nnn:
    • Check if an edge exists from X[k−1]X[k-1]X[k−1] to X[k]X[k]X[k].
    • Check if X[k]X[k]X[k] has not been visited earlier.
  4. When k=nk = nk=n, check if an edge exists from X[n]X[n]X[n] back to X[1]X[1]X[1]. If so, a valid cycle is found; otherwise, backtrack.

10.5 Traveling Salesperson Problem (TSP)​

  • Problem: Given a complete weighted graph G=(V,E)G = (V, E)G=(V,E), find a Hamiltonian cycle with minimum total edge weight.
  • NP-Hard Classification: Because finding whether a cycle exists is NP-Complete, finding the minimum-weight cycle across all (n−1)!/2(n-1)! / 2(n−1)!/2 permutations is NP-Hard.

11.3 Hierarchy of Computational Hardness​

  • An optimization problem is at least as difficult as its decision counterpart.
  • If the decision version is computationally hard (NP-Complete), the optimization version is automatically hard (NP-Hard).
  • An optimization problem can be solved by repeatedly querying its decision version using Binary Search over the bound ccc.
